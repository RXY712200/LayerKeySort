# Preview.1 实时顺序架构决定（历史译本）

Stable 根据 AVL 子树块数计算两个块各自的绝对秩。候选保留以前驱／后继链接串接的块、地址稳定的驻留记录和 AVL 索引。跨块比较时，沿父链接提升高度较低的一侧，直至两块互为兄弟，或一方是另一方的直接父块。沿父链接上移时高度严格增加，避免一侧先越过共同祖先。根据子链接所在方向判断先后。同块比较使用块内下标。子树块数仍由索引维护，并接受诊断检查；托管搜索与批量恢复的拓扑及契约保持不变。

插入设置新驻留记录的所属块，并从插入点开始更新块内位置。普通删除清空原尾槽，并更新发生移动的后缀位置。跨块移动更新目标位置；源块无需结构修复时，只更新移位的后缀。拆分、合并和重新分配会改变所属块，因此保留完整的位置修复。所有可能失败的分配仍在发布之前完成。记录、块及 Order 的对象尺寸保持不变。

研究用的动态 64 位中点标签原型保留 AVL 回退。端点按固定步长分配，内部拆分时取两个标签的中点。反复在内部锚点之前插入，到第 1,057 次插入时耗尽间隔。原型随后禁用该 Order 的标签，至 10,000 次插入时仍通过比较验证。它通过放弃标签快速路径来避免全局改写标签。性能退化和额外块存储使其工程价值仍待验证，候选构建未纳入该原型。

生产候选组合了基于祖先关系的比较和仅更新变更区间的做法。两者共用原有紧凑的稳定驻留记录表示。经典标签方法可以提供常数工作量的查询；这项比较优化不足以证明相同的复杂度或算法新颖性。快照及线格式保留原有所有权和执行次序。当时仍需进行跨主机、等价语义的测量才能验收。

## 先后不变量及先前设计

设两个不同块的最低共同祖先为 C。任一块在抵达 C 之前，其高度必然低于 C。因此，只要另一块仍在 C 下方，提升高度较低的一侧就不会越过 C。一次沿父链接上移如果直接到达对方，即为祖先关系；否则两条路径会分别到达 C 的不同子块，左子块先于右子块。旋转保持块的中序次序，同时重算高度与父链接。批量恢复建立相同的不变量。向上移动的总步数不超过两条到根路径的长度之和。以 M 为块数，耗时为 O(log(1+M))；同块比较仍为常数工作量。

Dietz–Sleator 和 Bender 等人研究插入及删除期间的先后关系维护。他们的结果提供机制层面的比较基准；组件对照还取决于身份封装、遍历、可恢复失败、保留存储及负载。实测的 j-hui tag-range 和 list-range 变体固定在 `ac4b902d103beb30cee3316d20cd10701f52d15a`，并保留归档中的 MIT 许可声明。这两种实用标签实现的测量范围只覆盖被测变体及其语义，无法据此推及文献中的全部最优算法或估计 Full 每项 API 保证的成本。

Full 将块顺序、驻留记录的身份和历史导出分开。普通移位只需改变块内位置，可以保留所属块，位置维护的优化正是利用这一点。标签探针揭示了集中插入耗尽间隔的情况，因此该候选保留基于 AVL 的先后比较，没有引入新的重标策略。历史 V3 的尾部成本证据说明应同时观察完整负载。本次原型结果为以后继续研究有界标签维护留下了空间。
