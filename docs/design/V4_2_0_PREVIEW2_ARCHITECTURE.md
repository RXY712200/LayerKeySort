This extension retains those files and the diagnostic monotonicity check at `c977b0fd14a501d769b9783bfdcc61266bd1b5ae`. ## Step 3 — complete lifecycle

Capture traverses the explicit or managed order or immutable Group sequence in O(N) and invokes the association callback once per occurrence. It copies the namespace and copies each borrowed association before advancing. The cumulative end array represents empty and nonempty rows. Namespace, header and rows share an allocation, and association bytes grow separately and trim before publication. The caller can reuse a scratch association and subsequently destroy or mutate the source. A marker is assigned or retained after successful byte capture; equal live revision identifies sequence currency and does not imply equal application payload bytes or namespace. Two same-revision captures therefore cannot be shared by revision identity alone.

Writing LKS4SNP1 stores the existing magic, reserved field, namespace length and row count, namespace and pairs of 64-bit length plus bytes. The reader performs a complete framing/counting/overflow pass before allocation, then allocates the unpublished snapshot and exact association buffer and copies the rows and bytes. Restore allocates an N-pointer array, uses the resolver in ordinal sequence, and starts balanced bulk construction only after all resolutions succeed. The old pointer scratch and copy semantics are retained. Interleaving resolve with bulk allocation would alter the call prefix observed on OOM. Capture/encode/decode remain O(N + namespace + association bytes); restore adds one bulk live construction and O(N) pointer scratch. That scratch does not change snapshot ownership or the output handles used after successful restore.

The fixed-width prototype and selected implementation read fields using unsigned 32-bit shift/OR composition, with a 64-bit result for eight-byte fields. Writing uses the corresponding unsigned shifts to individual bytes. All callers use widths four or eight. Existing checks bound the byte ranges before any read. Byte operations allow unaligned input, avoid native representation or endianness dependence, and retain the two-pass validation, allocation/failure order, resolver ordering and exact output bytes. The mechanism adds no allocations or fields. Each validation pass still examines all lengths and rejects bad trailing data. Existing golden, malformed and fault fixtures remain unchanged.

The independent comparison uses a linked sequence with one allocated node per occurrence and flat copied snapshots, common successful wire/ordinal/resolve semantics and an independent byte and ordinal oracle. This specific workload uses endpoint reordering, repeated capture and all-row key/encode/decode/restore. The list has no arbitrary precedence index, managed comparator invariants, provenance marker, or Full-like recoverable allocation and malformed-input policy. Its decoder allocates based on the trusted input size before its row pass and restores nodes while resolving. Report differences as costs of the tested compositions and guarantees. Wider retained and payload-variable cells bound the likely savings of fixed-width decode. No deduplication, cache, new sharing scheme or restore reordering is justified here.

## Step 4 — OrdWeave

OrdWeave `b12a007c50c2f9efcbee500a14d3cf09dcc74f10` owns persistent IDs, typed fields, collection membership, transaction publication, WAL durability and recovery. Its adapter uses Full for live relative order and managed lookups. In the core, TD-001 insertion and removal build an alternate global occurrence index before publication. That is an OrdWeave algorithm with O(N log N) construction and O(N) transient resident allocation. Its time contains actual Full managed insertions, traversal, allocation and the application comparator. It is distinct from one Full collection edit. Publishing then destroys the old index and backfills live index handles. A one-dependency swap cannot change this publication policy.

The structured application capture separates stage, publish, selected collection adapter calls and WAL commit; the main WAL flush is nested in commit. Exact-cell checkpoint, reopen and historical reconstruction are separate driver phases. Residual loop time retains lookups, comparator/layer costs outside measured spans, checking, and uninstrumented work. A general in-place multi-structure transaction cannot be inferred from the existing single-order call contract. The underlying Full dependency changes no adapter API, app source, recovery guarantees or persisted format. No alternative mutation policy or public API is selected in this package; validated-WAL replays and I/O semantics are retained.

## Step 5 — scale

Two million-to-one-percent survivor shapes test reclamation and surviving occurrence addresses through two shrink/regrow cycles. Retained snapshots are separately measured through their actual copied bytes and diagnostic counters. Once shrunk, sparse storage should track remaining residents and block occupancy rather than an allocation pool's historical high water. Original no-pool selection and capacity research remain available unchanged. Repeating stable survivors under clustered and scattered removal primarily tests block and resident reclamation. Process RSS is distinct from allocator-requested live and peak bytes, and a sampled lifecycle is not a bound on future allocator reuse, fragmentation or tag health.
