# Preview.1.2 有界块标签（历史译本）

原文：[V4_2_0_PREVIEW1_2_ARCHITECTURE.md](V4_2_0_PREVIEW1_2_ARCHITECTURE.md)，英文，固定于 [`c51e987aa1fda0b16bd61bae3f34ca1b6d091929`](https://github.com/RXY712200/LayerKeySort/blob/c51e987aa1fda0b16bd61bae3f34ca1b6d091929/docs/design/V4_2_0_PREVIEW1_2_ARCHITECTURE.md)。原件保留；[双语清单](V4_2_0_RC1_BILINGUAL_CHECKLIST.md)。

已采用的比较实现 `22544cf283694dd27cef203caba9cf1838845947` 按高度沿 AVL 父链接查找两个块的相对顺序。候选 `61e9290ec5ba47b9092bcb8ae7d61f13104ea839` 保留这条路径，并在每块增加一个私有的 64 位无符号标签。两块均有标签时比较标签值，同块则比较驻留记录的位置。任一块未标记时使用原有 AVL 比较。AVL 仍负责托管顺序的搜索及结构顺序维护。

## 维护与不变量

沿前驱／后继链接遍历块时，非零标签严格递增。零表示未标记。`v4_tag_attach` 逐步扩大新接入块周围的连续窗口，宽度最多为 64 块。外侧实际邻块必须有非零标签；缺少邻块的一侧使用端点哨兵。两界之间须有足够的无符号数间隔。重分配后，窗口内的标签严格位于两界之间，窗口外保留原值，整个非零序列仍有序。开放右端的单块赋值设有步长上限，为后续增长留出空间。步长计算先做减法再做除法，写入值受外侧上界约束。

局部赋值失败时，新块保持零标签。后续若修复窗口成功覆盖该块，可以补上标签，但策略不保证每个零标签最终都能恢复。每次接入最多检查 64 种窗口宽度，至多写入 64 个标签。删除块以后，其余块的标签顺序仍严格递增。AVL 旋转保留前驱／后继顺序。调整驻留记录时仍沿用原有的位置维护方式。`lks_order_bulk_build` 在批建时初始化间隔较大的标签。输入记录、快照及持久格式都不携带这些私有标签。

两个带标签的块比较只需常数工作。以 B 表示块数，AVL 回退耗时为 O(log B)。块接入增加的工作量有界，有限标签空间耗尽时由回退路径维持正确性。每块新增一个 64 位字段。修复不分配内存，也不调用回调。准备阶段、失败时的状态发布、修订号、空操作规则、驻留期间的地址和所有权规则均沿用原契约。

## 候选选择

Dietz 和 Sleator 的 1988 年技术报告区分了维护标签与比较标签的成本。Bender 等人（2002）采用间接表示及基于密度的标签维护。归档的 j-hui 实现采用 MIT 许可，其 tag-range 和 list-range 实现为各自的条目维护标签。这里的 C 候选独立实现有界重分配，作用于 Full 现有的驻留记录块，并保留结构回退路径。先行算法的完整理论保证不直接适用于此处的有界策略。

此前仅用中点赋值的原型约在第 1,057 次集中插入时耗尽间隔。本扩展实测能够重新分配标签的实现。去掉子树块数的消融对照在 Release 库上耗时基本持平，且不变量检查仍读取该字段，因此保留计数。[预定协议](../../benchmarks/research/full-v4.2.0-preview.1.2/PROTOCOL.zh-CN.md)和[阶段报告](../V4_2_0_PREVIEW1_2.zh-CN.md)记录了证据和门槛。
