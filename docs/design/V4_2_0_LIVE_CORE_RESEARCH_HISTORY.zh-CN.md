## 2. 为什么改变实时核心

原 V0.5 原生适配实验每平台 45 条冻结的 20,000 操作轨迹：1k/10k/100k，种子 17/305419896/2654435769，比较密集、更新密集、短、长、热点五型。五实现 4,050 次观测、3,150 次正式计时、独立复算 450 单元。Rust tag-range 两平台均 45/45 快于 Full，中位 Full/tag 为 Windows 1.9712、Linux 2.2124，比较密集 3.874/5.180，最差约 5.45。List-range 在 Windows 43/45、Linux 44/45 获胜。这些是原生组件对照，无法单独归因抽象算法或等价完整生命周期。100k、种子 17、比较密集时 Full 请求表示内存 3,875,768 字节，两个 OM 均 13,436,784。原轨迹、哈希及数据见上述公开归档；勿与后来候选计时当作同期数据。

v4.1.0 相对 4.0.0 降低内存：1m 追加请求 50,249,480 → 42,499,472 字节，1m/16 快照峰值 513,593,776 → 355,751,040，10m/2 快照 1,822,185,272 → 1,317,499,808。历史不利例含 Linux 3m 查找 +10.2%、4096 字节命名空间格式化 +25.1%，以原比较为准。[Stable 报告](https://github.com/RXY712200/LayerKeySort/blob/70d7f0ef5857b54381b863d292a213909d87459f/docs/V4_1_0.md)及[整合内存研究](https://github.com/RXY712200/LayerKeySort/tree/6325a6b16d2fe049b7bbc1227c017d6bfb5593b8/benchmarks/research/final-step3)。目标是在保留内存收益的同时调查速度损失，不能推断外部 OM 差异全源于 4.1.0。原跨块比较计算两个 AVL 绝对块秩，普通编辑重写所有居民的块/位置；据此形成可证伪方案。既有技术见 [Dietz–Sleator](https://www.cs.cmu.edu/~sleator/papers/maintaining-order.html)、[Bender 等](https://erikdemaine.org/papers/DietzSleator_ESA2002/)及固定的 j-hui/order-maintenance ac4b902d103beb30cee3316d20cd10701f52d15a（MIT；归档保留实际许可和源码）。

### 3.2 Preview.1.2：有界动态标签加速，保留 AVL 正确性核心

- 所有者批准扩展以调查经典 OM 差距；保留 Preview.1。结果前制定协议 d7e0fb1ab7b3cb8e1c8445648584155d0b61124e。每块新增私有 uint64_t；两带标签块 O(1)，同块按局部位置 O(1)，任一零标签回退到原高度引导 AVL O(log(1+M))，M 为块数。AVL 仍管理结构和托管查找。接入时最多检查 64 个宽度、写 64 个标签，无分配；失败保留零。成功区间可恢复旧零标签，但无普遍恢复或 O(1) 最坏保证。批恢复间隔赋值，旋转不改逻辑顺序，标签不序列化或公开。区别于简单中点的持续回退。移除计数的消融总体慢 .1%（1.0009），全测试又依赖计数，故否决并保留子树元数据。10 个预选条件的初查总体 .8871，比较密集 .3227。

## 4. 为什么选择 B64

这是两代历史容量选择，未证明 64 数学最优。

1. [V4 决策第 3 项](V4_DECISIONS.md)先选可调 B128。[V4 Preview.4](../V4_PREVIEW4.md)的一次调参测试 B64/B128/B256，10k/100k，端点、随机、本地拖动、远距拖动、周转、全等、重复、时间线，每份 96 行：[容量初查](../../benchmarks/results/v4-preview4/capacity-screen.csv)、[大规模](../../benchmarks/results/v4-preview4/capacity-large.csv)、[复验](../../benchmarks/results/v4-preview4/tuned-b64/capacity-screen.csv)。100k 八单元 B64 中位总耗时均较 B128 低约 7–27%，局部最大赋值约减半，请求存活及分配次数 +1–3%。B64 最小占用 32，65 行批恢复分成 33/32，物理块不进入线格式。保留前后记录，与 2026-11-24 筛查分开。
2. 4.1.0 降低居民与历史内存时特意保留 B64。范围更新与块标签改变成本模型，因此重测 B32/B64/B128。
3. 独立批建 100k 加 4,096 混合移动，B64 从 1,563 块到 1,605 块，1,306 同块、2,790 跨块，86 次目标满。
