Keep changing collections in order.

LayerKeySort gives items sortable position coordinates when a collection is repeatedly inserted into, removed from, or rearranged. Your application keeps each item's identity; a Path describes its current position.

Getting the code

One library, several ways to use it

For a small C project, download the two-file amalgamation from GitHub Releases. Copy layerkeysort.h and layerkeysort.c into your project and compile the implementation as C17.

Already using CMake? Choose FetchContent, add_subdirectory, or a local install with find_package. The integration guide has complete commands; 中文集成指南 covers the same first-use paths.

LayerKeySort 3.1.0 is the current Stable release. Its Release includes the amalgamation ZIP and a SHA-256 checksum manifest.

Which API?

  • LksOrderedTree keeps comparator order as items change.
  • LksTree lets the application choose positions.
  • lks_sort() stably sorts a pointer array once.

Before you adopt it

Measure the workload that matters to you

Managed insertion may relabel many Paths, sometimes the whole collection. Synchronous latency and Path storage depend on the workload. Paths are not permanent item IDs, and LayerKeySort is not distributed or CRDT ordering. For latency-sensitive use, read the benchmark evidence and test your own insertion patterns.
