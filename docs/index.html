Getting the code

One library, several ways to use it

For a small C project, download the two-file amalgamation from the Full v4.1.0 Release. Copy layerkeysort.h and layerkeysort.c into your project and compile the implementation as C17.

Already using CMake? Choose FetchContent, add_subdirectory, or a local install with find_package. The integration guide has complete commands; 中文集成指南 covers the same first-use paths.

LayerKeySort Full v4.1.0 is the current published Stable Release, with compatible memory optimizations, a verified amalgamation ZIP and SHA-256 manifest. Performance remains workload-dependent. V3.1.0 remains available for legacy Path/Tree contracts.

Which API?

  • LksManagedOrder binds comparator order; handle all affected occurrences across ManagedOrders and other sorted borrowers before changing keys. Reconstruct Group/Batch where needed; removal expires Handles, reinsertion can fail, and recovery is application-managed. See the complete usage contract.
  • LksOrder supports relative insertion and resident-preserving moves.
  • lks_sort() stably sorts a pointer array once.

Before you adopt it

Measure the workload that matters to you

V4 avoids live Path growth and collection-wide coordinate relabel. Local block/index work, allocation and comparator costs remain; full snapshot export and retained history can dominate time and memory. The strongest fit is a long-lived editor-like collection with repeated insert/remove/move operations, not one-shot sorting or distributed/CRDT ordering. Read the benchmark evidence, test your own workload, and follow the post-v4 roadmap.

多种集成方式

小型 C 项目可从 Full v4.1.0 发行页下载双文件合并包。复制 layerkeysort.h 与 layerkeysort.c 到项目，并按 C17 编译实现。

LayerKeySort Full v4.1.0是当前已发布 Stable，含兼容的内存优化、经过验证的合并包及 SHA-256 清单。性能取决于负载；旧 Path/Tree 契约继续由 V3.1.0 提供。

如何选用 API？

  • LksManagedOrder绑定比较器顺序；修改键前处理所有相关托管顺序及其他有序借用结构中的全部受影响实例，必要时重建Group／Batch。删除使Handle立即失效，重插可失败，应用负责恢复。参见完整使用契约。
  • LksOrder支持相对插入和保留居民实例的移动。
  • lks_sort()执行一次稳定指针数组排序。

测量自己的目标负载

V4 避免实时 Path 增长和全集坐标重标。仍有局部块及索引维护、分配和比较器成本；完整导出及历史保留可能主导耗时与内存。较适合反复执行插入、删除及移动的长期编辑型集合。一次性排序或分布式/CRDT 顺序有其他需求。参见 基准证据，运行自己的负载，并关注 V4 之后的路线。
