## 当前 V4 证据

[4.2 候选证据](FULL_RC1_EVIDENCE.zh-CN.md)比较同条件的 Windows/Linux 实时顺序、生命周期墙钟时间及内存。使用运行源码不变的 Preview.3 归档测量。

[Preview.4 采集证据](../benchmarks/results/v4-preview4/README.md)记录 V4 历史收敛。认可的三步 Full 4.1.0 研究涵盖 100k–10m；原始运行见[最终研究分支](https://github.com/RXY712200/LayerKeySort/blob/6325a6b16d2fe049b7bbc1227c017d6bfb5593b8/benchmarks/research/final-step3/REPORT.md)。1m/16 个历史保留状态的请求峰值由 513.594 降至 355.751 MB；通过准入的 Linux 10m/2 为 1,822.185 降至 1,317.500 MB。这是 Full 请求字节，RSS 另计。Linux 3m 随机查找相对原始 4.0.0 慢约 10.2%，还有其他退化场景。不存在通用加速结论。

- 普通实时修改无需全集坐标重写。
- 在选用的表示中，移动的结构工作与逻辑距离无关。
- 局部块及索引维护由私有块策略和均衡索引工作约束。
- 快照和导出的成本独立于实时修改。
- 保留快照占用的内存与实际保留的历史状态成比例。
- 分配、比较、回调、块空余和局部指针操作仍有成本。

一项 Preview.4 大型 timeline 测量含初始 100k 居民及 100k 操作，该设备总计 28.912 ms。单操作观测最大为 95 次记录位置赋值、2 个局部数组及 15 个索引块更新。测量不构成延迟界或通用加速。Stable 4.0.0 未重复调优，针对性回放保持冻结结构计数。

### 尚缺什么

证据广泛但主要来自确定性合成或应用形态负载。后续测量应回答具体正确性、性能、分配器、可移植性或集成问题。真实编辑器轨迹有帮助，外部采用并非前置条件。有限三步研究已结束，后续参见 [Issue #3](https://github.com/RXY712200/LayerKeySort/issues/3)。

## 可比 V3 插入矩阵

历史 V3 RC.1 保留 Preview.3 算法。单机 100k–1m 托管 Tree 插入显示明显负载差异。[计时 CSV](../benchmarks/results/v3-preview3-validation-timed.csv)、[诊断采集](../benchmarks/results/v3-preview3-validation-diagnostics.txt)和[方法](../benchmarks/results/v3-preview3-validation-metadata.md)均保留。各行使用相同源码及编译器；1m 耗时为单次运行。

| 插入模式 | 100k ms | 1m ms | 1m 全区间重标 | 1m 最终居民 Path MiB | 1m 估计 LK1 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 升序 | 54 | 2,428 | 1 | 112.5 | 53.8 |
| 降序 | 36 | 411 | 0 | 45.8 | 14.3 |
| 随机唯一 | 99 | 2,277 | 1 | 69.1 | 29.8 |
| 全等 | 54 | 2,447 | 1 | 112.5 | 53.8 |
| 32 值重复 | 109 | 5,007 | 2 | 96.2 | 40.3 |
| 高低交替 | 1,655 | 44,023 | 56 | 98.5 | 40.8 |
| 固定内部热点 | 38 | 418 | 0 | 45.8 | 19.8 |

高低交替重复接近两个端点，1m 时有 353,830 次成功重标，累计 69.4 百万次旧坐标替换及 56 次全区间。最终 Path 深度平均 4.47、最大 6。主要成本为重标和分配周转；观测未显示最终深度失控。独立逐插入探针在交替中观察到超过 700 ms、在重复模式中超过 1 秒的停顿。方法和限制见元数据。数十万规模须有稳定低同步延迟的应用应实测或选用具有合适保证的方案。完整插入无最坏 O(log n) 或形式摊还界。

## 测量边界

[采集元数据](../benchmarks/results/v3-preview3-validation-metadata.md)记录提交、Windows、MSYS2 UCRT64 GCC 16.2.0、参数、种子、重复数及计时/诊断分离。计时排除准备、输出验证及销毁。100k、300k 各预热一次重复三次；500k 预热一次重复两次；1m 不预热运行一次。诊断计数不是额外计时观测。独立逐插入探针测量尾延迟，最大值仅为观测。[程序指南](../benchmarks/README.zh-CN.md)说明复现。当时 V3 包含升序、降序、随机、全等、重复、交替和固定热点。

`relabel.nodes_relabelled` 统计成功托管插入替换的旧坐标，`max_region_nodes` 为最大成功区间。存储记录给出最终居民 Path 分配、步骤总数及显示/LK1 C 字符串字节。这些指标独立于墙钟时间，不能建立渐近界。

## V3 顺序的复杂度与限制

令 `n` 为 Tree 大小、`d` 为 Path 深度、`b` 为编码长度、`c` 为调用方比较器成本。AVL 访问还可能比较 Path，开销最多 O(d)。下表描述历史 V3 的结构工作，适用时计入输出；不提供每种分配或硬件成本的形式界。

| 操作 | 历史 V3 的结构工作或注意事项 |
| --- | --- |
| Path 比较 | O(min(d1,d2)) 步比较。 |
| 显示/键长度和格式化 | 迭代 O(d + b)，格式化无库分配。 |
| 显示/键解析 | 迭代 O(b) 语法加 Path 分配/增长；畸形和溢出均干净失败。 |
| 显式 Tree 查找 | O(log n) AVL 访问，每次 Path 比较最多共享深度。 |
| 显式 Tree 插入 | 同查找，加克隆 Path 和 O(log n) 重平衡，无修复策略。 |
| 托管 Tree 定位 | 比较器一致时调用 O(log n) 次，返回借用节点。 |
| 托管直接间隙插入 | 上界查找及生成间隙，随后 O(log n) Path 索引插入；计入 c、Path 比较及分配的候选深度。端点进位最多扫描/复制至 Path 深度。 |
| Tree 删除 | O(log n) 索引查找与平衡，加 Path 比较及销毁；无分配。 |
| Tree 改键 | 两次索引查找及 O(log n) 结构工作，加克隆/新节点分配和旧 Path 清理；相同坐标成功为无操作。 |
| 自适应重标 | 从八个逻辑邻居开始，按需扩大一倍。成功的 k 节点窗口准备 k + 1 个 Path，替换 k 个旧坐标，可能触及全部 n 个节点。失败尝试也需生成及分配。 |
| 全区间重标 | 准备 n + 1 个新 Path，交换 n 个旧坐标，链接一节点，保持物理 AVL 索引。峰值包括旧及准备中的 Path 与暂存。 |
| Group 构建 | 稳定排序 O(n log n) 次比较，再生成 Path、建 Tree 及验证；Path 工作另计。 |
| Group 合并 | 稳定合并按项数线性遍历两个已排序输入，再构建并验证全新 Path 空间。 |
| lks_sort | 稳定归并排序，O(n log n) 次比较、O(n) 指针暂存、O(log n) 递归深度。 |

自适应重标可触及每个坐标，完整托管插入无保证的 O(log n)；也不声明形式摊还界或固定深度/内存上限。历史 V2 全重建计数不同于 V3 全区间重标；V3 有独立的频次与影响坐标诊断。LK1: 数据库排序应采用 ASCII 字节顺序。
