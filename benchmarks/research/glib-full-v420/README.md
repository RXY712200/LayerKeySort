# Native GLib versus Full v4.2.0

The executed comparison is in [REPORT.md](REPORT.md). All 384 samples, including warmups, are in [results/raw.csv](results/raw.csv). The campaign uses actual MSYS2 UCRT64 GLib 2.90.1 and released Full v4.2.0; it does not emulate GLib or change production code.

## Reproduce on native Windows x64

Requirements: Git, Python 3, Windows `tar` with Zstandard support, MSYS2 UCRT64 GCC 16.2.0 and the native runtime dependencies of the GLib package. This run used the existing `D:\msys64\ucrt64\bin` installation, including `libffi-8.dll`, `libpcre2-8-0.dll`, `libintl-8.dll`, `libiconv-2.dll` and `zlib1.dll`. Their hashes and PE import lists are archived in [dependency-provenance.json](results/dependency-provenance.json). Do not substitute MSYS POSIX GLib for UCRT64 GLib.

From the repository root:

```powershell
python benchmarks/research/glib-full-v420/run.py --gcc D:\msys64\ucrt64\bin\gcc.exe --smoke --output build/glib-smoke
python benchmarks/research/glib-full-v420/run.py --gcc D:\msys64\ucrt64\bin\gcc.exe --output build/glib-reproduction
```

The runner downloads the exact official binary package into ignored `build/glib-deps`, extracts it locally, checks the Full source against the release SHA, builds one native executable with both adapters, and runs the four scales serially. It changes PATH only for its child processes. No machine-wide installation or production build change is performed. On the original run the GLib package SHA-256 was `9a7826349279bcca0c935b01880d812be9de9609aef2205be68fd7a6128c1695`; compare the replay's `environment.json` before interpreting its results. If the package has moved, obtain the same version from MSYS2 archives and verify that hash rather than silently changing versions.

The 180-second per-process timeout and physical-memory admission guard are part of the protocol. Failures and skips remain in `exceptions.json`. Each sample validates output outside timing. The complete initial campaign passed every oracle and admitted every size, including one million elements. Approximate timings depend on the host and scheduler; binary and package identities, traces, semantic checks and workload definitions are the reproducibility targets, not identical wall-clock measurements.

To regenerate the checked-in comparison tables/report **without rerunning experiments**:

```powershell
python benchmarks/research/glib-full-v420/analyze.py
```

This analyzer reads the preserved `results` directory and checks row counts, measured repetitions and pairwise trace/result equivalence. Keep new measurements in a separate output directory; do not overwrite captured evidence. `summary.csv` is generated by `run.py`; `comparisons.csv` and `REPORT.md` are generated by `analyze.py`. Exact original compile arguments and environment are in `results/environment.json`. Recorded file hashes describe the Windows working files used for execution; Git can normalize text line endings on other platforms.

## Evidence interpretation

- Timing is the selected public-API loop, excluding setup, independent oracle and destruction. Insertion starts empty; other sequence workloads start populated. Array-sort cells time one sort, not N separate sort calls.
- Memory is Windows **whole-process peak resident working set and peak private commit**, including the common harness and validation. It is not requested allocation bytes or isolated container storage. Baseline working set is also retained.
- Managed lookup matches predecessor/equal/successor on unique keys. Array sorts verify tie stability using original occurrence IDs. Mixed queries are adjacent-pair queries; the separate precedence workload uses random pairs.
- Both sides use native release optimization. Full/harness use GCC `-O3 -DNDEBUG`, and the hash-matched GLib packaging recipe uses Meson release mode with debug disabled. GLib's exact package build command is not controlled by this harness; its upstream `.BUILDINFO` is preserved.
- No OOM-policy equivalence, general superiority, asymptotic guarantee or cross-platform result is inferred. The initial report retains GLib's sorting wins and Full's unfavorable memory comparisons.

## Upstream package provenance and licensing

GLib is LGPL-2.1-or-later according to its archived `.PKGINFO`. No GLib DLL, import library, header tree or package archive is committed here. Obtain them from the official [MSYS2 package endpoint](https://repo.msys2.org/mingw/ucrt64/mingw-w64-ucrt-x86_64-glib2-2.90.1-1-any.pkg.tar.zst). The [exact packaging recipe](https://github.com/msys2/MINGW-packages/blob/8718c5b0ed6a01bf4b6fdd7b275a620586adf90b/mingw-w64-glib2/PKGBUILD) SHA-256 matches the package's `pkgbuild_sha256sum`; it identifies the upstream GLib source and patches. Research harness code uses the repository's MIT license. Package metadata is retained solely as upstream provenance.
