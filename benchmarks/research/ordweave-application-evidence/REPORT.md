# OrdWeave downstream application evidence — Full v4.2.0

Reviewed 2026-11-27. This is the LKS project's bounded review of the downstream OrdWeave team's Preview.1–4 handoff, not a new benchmark campaign or a database release acceptance.

## Decision

**Application-value validation: PASS at the current stage.** Actual integration and measurable downstream benefits are supported by the pinned evidence below. Reverse reliability validation remains incomplete. The two objectives are independent.

OrdWeave is a Windows x64 C17 embedded database. Its published v1.0.0 Stable uses Full 4.1; its v1.1.0 development line uses released Full v4.2.0 at `f751e1ee2afd682874281d6dc495969f9eca49eb`. The reviewed Preview.3 production commit is `edb9675b10125cecdf936e030bd9a54a90a84146`; the latest inspected Preview.4 research/documentation head is `cf342dcf881bc9e3518ede042baeaed25f807da7`. The latter retains the existing 44 public APIs. The downstream team's later approved four-API implementation is in progress according to its handoff; it is not accepted as production evidence here.

## Actual application

Direct inspection of [OrdWeave production code](https://github.com/RXY712200/OrdWeave/tree/edb9675b10125cecdf936e030bd9a54a90a84146/src) and its dependency gitlink confirms collection-relative insert/remove/move/traversal/precedence through LksOrder, permanent Record and Collection ID indexing through LksManagedOrder, and checkpoint capture/serialization/deserialization/restore through LksSnapshot. OrdWeave retains ownership, durable IDs, revisions, WAL, integrity, retention, recovery and backup responsibilities. Its own compressed radix occurrence-ID index coexists with LKS collection order.

Source anchors: [adapter](https://github.com/RXY712200/OrdWeave/blob/edb9675b10125cecdf936e030bd9a54a90a84146/src/lks_adapter.c), [runtime](https://github.com/RXY712200/OrdWeave/blob/edb9675b10125cecdf936e030bd9a54a90a84146/src/ordweave.c), [checkpoint](https://github.com/RXY712200/OrdWeave/blob/edb9675b10125cecdf936e030bd9a54a90a84146/src/checkpoint_core.inc), [radix index](https://github.com/RXY712200/OrdWeave/blob/edb9675b10125cecdf936e030bd9a54a90a84146/src/occurrence_index.inc).

## Limits

The review checked remote pinned reports, source call sites, gitlink, release metadata, summary files and selected raw files, without rerunning benchmarks. Generated workloads on one Windows host with limited repetitions cannot establish broad reliability, cross-platform generalization or statistical significance. Requested allocation bytes are not RSS. Preview.4 integer index maintenance is phased, and all-type production lifecycle behavior remains unverified here. The downstream EG-003 checkpoint OOM classification anomaly remains unresolved and was not reproduced by subsequent targeted checks; no evidence attributes its cause to LKS. [Original failure](https://github.com/RXY712200/OrdWeave/blob/f1c39a2fde1eadd39bdf3a7b5e8bb6d135f58ade/handoff/v1.1.0-preview.1/initial-Release-ctest-failure.log).

Do not multiply different-stage speedups or attribute database architecture improvements to LKS alone. Do not infer superiority over other databases, or replace component-level GLib comparisons with this application case. No claim of completed reverse reliability validation.

This archive changes no production source, API, format, technical-debt status, version, tag or release. No further experiment is authorized by this review.
